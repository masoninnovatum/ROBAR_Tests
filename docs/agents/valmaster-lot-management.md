## Print Entity (PE.161004)
- **F.7.1** The module takes Print Entity into account only when `PrintEntityRequired` = Y (owner Innovatum or Innovatum.DataManagement.Web). With N: the Print Entity dropdown is NOT displayed in the Add Record / Edit Record dialog, Print Entity is set to ROBAR automatically, search results are not limited by Print Entity.
- **F.7.2 / F.7.3** (TRS) `PrintEntity` nvarchar(30) NOT NULL, part of the Lots primary key, never blank. **F.7.4** same lot / order with different entities are different records (key = Lot Number + Order Number + Print Entity). **F.7.5** FIELDDEFS row for lots.PrintEntity (ScreenPosition 11, caption "Print Entity", ReplacementString L_PrintEntity). **F.7.6** Print Entity column in the grid. **F.7.14** L_PrintEntity prints the lot's Print Entity.
- **F.7.7** search results are limited to Print Entities (active AND inactive) associated with the user. **F.7.8** a user with ALL (`*`) is not limited. **F.7.9** the Print Entity dropdown is pre-populated and LOCKED in the Lot **Edit** Record dialog when the user has only one entity. **F.7.10** the Add dialog's dropdown contains only ACTIVE entities of the user (all entities for `*`). **F.7.11** if ALL of the user's entities are inactive, the Add dropdown is blank and grayed out. **F.7.12** Submit is disabled when the dropdown is blank. **F.7.13** a user not present in the User Print Entity table cannot view, add or edit any lot.
- **F.8.1** with Y, an Excel import is validated so the entities in the sheet match the user's. **F.8.2** a PrintEntity not assigned to the user -> "Print Entity is not linked to UserID: XXXXX." and the job cannot complete. **F.8.3** with N, a blank PrintEntity cell -> validation fails with "ROBAR is a required value for this column". **PE.161004.U.7 / U.8** maintain / import print entity information in Lot Management.
