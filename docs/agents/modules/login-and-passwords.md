## Login pages: legacy WebMenu vs the "new web menu" login (source + live URL check, 2026-10-07; for the password-settings matrix, DIT #6511 / #6512 side quest)
- **Legacy login** = WebForms `Web/WebMenu/Default.aspx` (+ `MainMenu.aspx`, `ChangePwd.aspx`), URL `http://<server>/innovatum/WebMenu/` (this is the URL in `ROBAR_BASE_URL`; fields `.userID`, `.Password`, `.loginBtn`, Language dropdown, footer "Web Menu Login <version>"; error text shown in the page e.g. "User account is disabled."). `UserLogin_LoginRedirect` sends an expired password to `~/WebMenu/ChangePwd.aspx?Expired=true`. It uses `InnoUser` (Lib) for the checks.
- **NEW login page** = the ASP.NET MVC project `Innovatum.WebMenu` ("new web menu"), installed as its OWN IIS website `InnovatumWebMenu` in the folder `ROBAR` (`Website_Installer("Innovatum.WebMenu", "InnovatumWebMenu", "ROBAR")`), so the URL is **`http://<server>/ROBAR/`** (also `/ROBAR/Account/Login`); live on both TST703 and VAL703, `<title>ROBAR Web Menu</title>`. Route `{controller}/{action}`, default `Account/Login`; main menu route `WebMenu/MainMenu`. Login view `Views/Account/Login.cshtml`: `#userIDInput`, `#passwordInput`, Language dropdown, submit "Login", optional Microsoft / OKTA login buttons (OpenID_* global settings of owner `Innovatum.WebMenu`, `autoOpenModuleName`/`autoOpenDocumentID` deep links, `AutomaticLogin` action), `LogOff`, `TimedOut` (`WebTimeoutInMinutes`, default 60). Controller `Controllers/AccountController.cs`: `Login` POST builds `InnoUser(userId, password, machine)`; **if `PasswordIsExpired` (and not AD-authenticated) it shows the `ExpiredPassword` view** (`Views/Account/ExpiredPassword.cshtml`, old password + new + confirm). `ExpiredPassword` POST enforces, in order: new = confirm, `PasswordMinLength`, `PasswordNeedsLetters = Y` (regex `[A-Za-z]`), `PasswordNeedsNumbers = Y` (regex `[0-9]`), `ChangePasswordDB.PasswordNotAvailableForReuse` (`PasswordDaysBeforeReuse`), old password correct, new != old; then `ChangePasswordDB.SaveNewPassword`. Messages come from the `Innovatum.WebMenu.ExpiredPassword` resources (`passNotMatch`, `passMinLength`, `passContainLetters`, `passContainNumbers`, `passNotReusable`, `oldPassIncorrect`, `newPassDifferent`), login errors from `WebMenuErrorKey` (`errInvalidPassword`, `errTimedOut` ...).
- **Password-related Global Settings** (defaults from `GlobalSettingsDefaultRecords_LegacySettings.cs`, owner Innovatum): `PasswordChangeDays` 90, `PasswordChangeOnReset` Y, `PasswordDaysBeforeReuse` 365, `PasswordFailLockCount` 3, `PasswordMinLength` 5, `PasswordNeedsLetters` Y, `PasswordNeedsNumbers` N (the Lib `SystemSettings` also exposes `ADAuthentication`). Files that READ them: `Lib/.../Security/InnoUser.cs` (expiry via `PasswordChangeDays`, lockout via `PasswordFailLockCount`), `Web/WebMenu/ChangePwd.aspx.cs` (legacy change / expired), `Innovatum.WebMenu/Controllers/AccountController.cs` (new login, expired), `Innovatum.UserMaintenance.MVC|WCF` (`PasswordResetController` / `PasswordResetService` = the Password Reset module), the `InnoUserMembershipProvider.cs` copies (Web, Pages.Web, DataManagement.Web, WebMenu), `Lib/.../WebMenu/Database/ChangePasswordDB.cs`. **The Security Management project does NOT appear in that list: creating / editing a user there does not read `PasswordMinLength` / `PasswordNeedsLetters` / `PasswordNeedsNumbers`** - consistent with DIT #6512 (Lan Ho: the rules only work in the new web menu / ChangePassword page; Mark Fredrikson: a user created with a non-conforming password and "reset password at next logon" unticked slips through; Harini: DIT is for 7.0.3 only, no legacy software change).
- Our Playwright helpers (`tests/support/robar.ts login/loginAs`) use the LEGACY URL and selectors; a new-login helper would use `/ROBAR/` + `#userIDInput`/`#passwordInput`.

### Password settings x surfaces: source trace + formal scripts (2026-10-07; basis for the password-settings test matrix; behavior INFERRED FROM CODE until the matrix runs live on TST703)
**Names/scope (user, 2026-10-07):** the "new login" = the **Web Menu Improvements** project (requirements `WMI.230612.F.*`; formal scripts `\diskstation\backedup\#Unlocked_Test_Cases\Web_Menu_Improvements\Web_Menu_Improvements-1.doc` / `-1.1.doc` (password reset + auto-open module) / `-1.2.doc` (notifications, dashboards, favorites)); its "password reset page" = the **ExpiredPassword** page shown at login (script 1.1 step 1.3: UserID, Old Password, New Password, Confirm New Password, Submit + Cancel). Surfaces for the matrix: (1) New login page, (2) New login's password reset (ExpiredPassword) page, (3) Security Management, (4) Password Change module, (5) Password Reset module. Settings: PasswordChangeDays, PasswordChangeOnReset, PasswordDaysBeforeReuse, PasswordFailLockCount, PasswordMinLength, PasswordNeedsLetters, PasswordNeedsNumbers. **GlobalSettings owner of these seven is `LegacySettings`** (formal script 1.1 prerequisites; seed file `..._LegacySettings.cs`) - NOT `Innovatum`, so `readGlobalSetting(page, name, 'Innovatum')` returns undefined for them (cost a 5-minute run); the formal-script expected values are MinLength 5, NeedsLetters Y, NeedsNumbers N, DaysBeforeReuse 365, ChangeDays 90.
**New main menu (live, TST703 /ROBAR/):** login page = Innovatum logo, UserID / Password / Language, "Log In" (no forgot-password or reset link). After login: header "☰ Modules" slide-out alphabetical module list with favorite stars (starred modules, e.g. Label Control and Security Management for MBUser1, auto-open as tabs), "Demo Power BI" dashboard, user label "[MBUser1]", language dropdown, "Log off", "Help", notification bell, gear icon; modules open as header tabs (with x) and look exactly like the legacy menu. **"Password Change" tile = legacy `http://<server>/Innovatum/WebMenu/ChangePwd.aspx`** (form: Username, Current Password, New Password, Confirm New Password, Submit; tile seed `MenuWebIntegration` process `PasswordChange_Option`, default N; `?Expired=true` shows "Your password has expired. Please update your password now."). **"Password Reset" tile = `http://<server>/Innovatum/PasswordReset/`** (project Innovatum.UserMaintenance.MVC; takes about 10-15 s to load; process `ResetPassword_Option`): `drpUserReset` (users that are not AD users; MB users shown), `drpUnlockUser` (`drpUserUnlock`; locked users are listed with " - Locked" e.g. MBPWU524195 / MBTestUser1), radios `radReset` / `radUnlock`, `chkTemporary` ("Require user to change password on login", ticked by default; unticking needs process `ResetPassword_Nontemporary`), `txtNewPassword`, `txtConfirmPassword`, signature block `SignatureModel_UserName/Password/ReasonCode/Comment`, `btnSubmit`, and HIDDEN fields carrying the live rules `needsNumbers`, `minLength`, `needsLetters` (TST703 right now: minLength 5, needsLetters true, **needsNumbers TRUE** - differs from the default N). `ResetPassword_AllFacilities` is needed to see users of other facilities.
**Enforcement table (from code):** PasswordChangeDays: only `InnoUser.PasswordIsExpired` (`Now > Users.PasswordSet + days`; a reset or "reset at next logon" is done by backdating `PasswordSet`: Password Reset temporary = Now - 100 years, Security Management add with "Reset password at next logon" = 1900-01-01) -> new login pushes expired users to ExpiredPassword, legacy login to `ChangePwd.aspx?Expired=true`; AD users skipped. **PasswordChangeOnReset: seeded but NEVER read by any code** (the "Require user to change password on login" checkbox / reset flag decide). PasswordDaysBeforeReuse: `ChangePasswordDB.PasswordNotAvailableForReuse` against table `oldpasswords` (User, PWD, DATEUSED = when the old password was retired; the CURRENT password is not in it, so reusing the current one is not blocked by reuse) - enforced in Password Change ("That password cannot be reused at this time!"), Password Reset (folded into "The new password was invalid."), ExpiredPassword ("That password cannot be reused at this time"); NOT in Security Management. PasswordFailLockCount: `InnoUser` constructor: lock check first (`FailCount >= count` -> "User account has been locked out." even with the right password, AD users skipped), then Enabled != Y -> "User account is disabled.", wrong password -> FailCount+1 and at >= count `Enabled = N`; success clears FailCount; the new login hides all of it behind one text "Invalid UserID/Password" (reason only in the Activity `LoginFailed` row); unlock = Password Reset module (Unlock or any Reset sets FailCount 0 + Enabled Y); **Security Management's edit "Active" tick does NOT clear FailCount** (UPDATE never touches PWD/PASSWORDSET/FAILCOUNT), so a re-enabled user can still be "locked out" (untested). PasswordMinLength (`length < min` fails, so == min passes), NeedsLetters (`== "Y"`, regex `[A-Za-z]`), NeedsNumbers (`== "Y"`, regex `[0-9]`): enforced in Password Change (messages "Your password must be at least N characters!", "...must contain letters!", "...must contain numbers!"), Password Reset (JS: "Password is too short. Required characters: N", "Password must contain letters.", "Password must contain numbers."; server: "The new password was invalid."), ExpiredPassword (messages "Your new password must be at least {0} characters", "...must contain letters", "...must contain numbers"; also "Passwords do not match", "Old Password is incorrect", "New password must be different than the current password"); **NOT enforced anywhere in Security Management add/edit user** (only "Password is required" and "Password values do not match"; optional `AddEditUserStoredProcedure` global setting could add rules) = DIT #6512; the Login POST itself never checks complexity. Order quirks: Password Change checks policy/reuse BEFORE the current password (a wrong current password + a bad new one shows the policy error and does not count a failed attempt; wrong current password with a good new one increments FailCount and can lock); Password Change needs no login (any user with a known current password); ExpiredPassword POST does not verify the password is actually expired. New login adds a throttle: more than 3 attempts per user in 60 s are delayed (100 ms x n up to 3 s), more than 50 = "Excessive login attempts detected, access denied.". Settings are cached in a static dictionary (`SystemSettings.GetSetting`), so a Global Settings change needs a ServiceHost restart + IIS reset (formal scripts say so too); a blank/non-numeric numeric setting throws (FormatException) in the page code, a missing one "Setting X not found".
**Formal scripts read:** Web_Menu_Improvements-1.1 (login errors "Invalid UserID/Password" for unknown or wrong password; ExpiredPassword page for a brand-new user that never logged in; messages above; success -> main menu; DB checks `Users.LastTouch/PasswordSet`, `X_Users` ChangeType 'A'; `?moduleName=Print History Inquiry` auto-open), PR_PasswordReset1.1 (reset / unlock rules, "Password reset successfully", "User unlocked successfully", Locked label, facility rule, AD users not listed, Activity table), PR_UnlockAccount1.2, PasswordReset1. Note the 7.0.3 UI messages differ slightly from some older script wording ("User account is locked out" vs the code's "User account has been locked out.").

#### Password matrix R1 live results (TST703, current values 90 / Y / 365 / 3 / 5 / Y / Y, 2026-10-07) - the source trace above was CONFIRMED live
- **Security Management (DIT #6512 reproduced):** adding a user with `a` (1 char), `123456` (digits only) and `abcdef` (letters only) is ACCEPTED and each user then logs in on `/ROBAR/` straight to the main menu (reset tick off). The only add-user checks are "Password is required" (blank) and "Password values do not match". "Reset password at next logon" ticked -> first login shows the Expired Password page; unticked -> main menu. The edit dialog hides Password / Confirm / Reset (only Active, AD). After 3 wrong logins a user shows Active unticked; **ticking Active again in Security Management does NOT unlock** (right password still "Invalid UserID/Password") - only Password Reset > Unlock or a reset does. Add-user dialog selectors: `#users_input_userid|fullname|timezone|group|password|confirmpassword|resetpassword|active`, messages in `.SMValidation` (`sec.dialogMessages`); the dialog stays open on a validation error.
- **New login (`/ROBAR/`):** unknown user and wrong password both = "Invalid UserID/Password"; N-1 wrong attempts then a correct one clears the counter; the 3rd wrong attempt locks (the right password is then refused with the same generic text; a DISABLED user shows the same text too); more than 3 attempts in a minute are slowed (6 quick attempts took 2.5 s, 2.5, 2.5, 3.1, 3.1, 3.2 s). Selectors `#userIDInput`, `#passwordInput`, `input[type=submit]`, error `.text-danger`; a correct login with an expired password shows the Expired Password page with "Your password has expired and must be reset".
- **Expired Password page:** `#oldPasswordInput`, `#newPasswordInput`, `#confirmNewPasswordInput`, Submit, and a button labelled "Reset" (id `passwordResetResetBtn`; the formal script calls it "Cancel"); UserID shown disabled. Messages confirmed exactly: "Your new password must be at least 5 characters", "...must contain letters", "...must contain numbers", "Passwords do not match", "New password must be different than the current password", "Old Password is incorrect", "That password cannot be reused at this time" (both the password retired by an EP change and the one retired by a reset), success = main menu. Exactly 5 characters passes.

- **Customer report "NeedsLetters / NeedsNumbers enforced although disabled" (follow-up, TST703, both N, restart + reset done):** NOT reproduced on any surface - digits-only, letters-only, symbols-only and mixed-case 8-character passwords were accepted by the Expired Password page, Password Change, Password Reset (with login afterwards) and Security Management; stored values read "N" / "N" (owner LegacySettings), hidden fields false/false. Code-based candidates for the customer's symptom: each process caches the settings (`SystemSettings.GetSetting` static dictionary reloaded only when a key is missing; `PasswordResetService` reads them once in its constructor) so a change needs BOTH the ServiceHost restart and the IIS reset (new web menu site /ROBAR, Innovatum site, UserMaintenance site, ServiceHost); the typed `SystemSettings.PasswordNeedsLetters/Numbers` properties default to TRUE when the row cannot be read; the membership provider maps NeedsNumbers to `MinRequiredNonAlphanumericCharacters`; `SystemSettings` reads the legacy `Settings` table. A partial-restart experiment (set Y with full restart; set N; restart only ServiceHost, test; restart only IIS, test) would settle it - proposed to the user, not run.
