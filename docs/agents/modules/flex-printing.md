# Flex Printing - Playwright-confirmed 2026-10-12 (TST703, 7.0.3.20260; specs tests/Flex-Printing/; requirements valmaster-flex-printing.md, 26 rows)
**What it is:** tile "Flex Printing" (Printing section, process `BP_FlexPrinting_Option`) = legacy print screen `Innovatum/ROBAR/printing/Screens/PrintScreen.aspx?ConfigName=FlexPrinting` (code `Web/ROBAR/Printing/Custom/WebPrint/WebPrintFlex.cs`). Same page family as Print by Order / Lot: entry panel -> Next -> Lot Panel (Override Lot, Order, Expires, Manufactured, Reassay, U1..U5, Allow Label Control Selection) -> Next -> label screen (label type, Label Control, Copy, Printers, Reprint, Test, preview drop-down, View / Test Print buttons). No formal scripts exist for 7.0.3 (only the 6.0.7 LHS date-picker scripts).
**Entry fields come from PrintConfig rows** (`Flex_Identifier_n` = `<FlexLot_field>, <caption>[, AddOnly][, Date][, Protect]`; `FlexLot_ItemNumber`, `FlexLot_LotNum`, `FlexLot_OrderNum`, `FlexLot_Expires` ...). Plain identifiers are shown at once; `AddOnly` ones appear only after a lookup needs them. Config check (source): there must be a non-AddOnly Lot or Order identifier AND an Item identifier (non-AddOnly, or DeleteLotIfExists = N), else "Insufficient lot identifiers configured". Input ids end `customControl_txtItemNumber` / `_txtLotNumber` / `_txtOrder` (Order!) / `txtFlexLot_Expires`; buttons `#ctl00_btnNext`, `#ctl00_btnResetAll`. Chrome shows "Open SentinelLauncher?" when the screen opens (confirm with FlaUI; focus then sits in the first field - DIT #6617).
**TST703 FlexPrinting config (read 2026-10-12, 67 rows):** TestPrintShow Y, TestPrintDefaultChecked Y, TestPrintRequiredForSession Y, AllowManualDateEntry Y, AddLotReasonRequired N, LotMustExist N, DeleteLotIfExists N, LotDeBypass N, PrintPreviewOptions "Select Option, View Master, View Preview, View Compare", ClientPrintMethod Sentinel. Identifiers were `_1 Item`, `_2 Lot`, `_3 Item (duplicate!)` + `Flex_Identifier_3#` (disabled; `FlexLot_Expires, Expiration Date, Date, Prot@ct` - note the "@" typo). **The duplicate Item identifier made Next crash with an unhandled "Server Error" for any input**; Claude (user allowed, via Print Config Management, no restart needed) changed `_3` to `FlexLot_OrderNum, Order Number, AddOnly` -> everything works. This is the standing config; specs that vary it restore it in `finally`.
**Behavior (live):**
- Existing lot: Item + Lot -> Lot Panel shows the lot's Order (FLX.190301.F.1.5 ok). With config Order + Item (Lot AddOnly) -> Lot shown (F.1.6 ok). With Order + Lot and Item AddOnly -> the lot's item is shown in the panel (F.2.3 ok).
- Messages (shown under the fields): blank entry "No item found."; unknown item "No item found. <item>"; unknown lot "No Lot found for this order/lot/item combination. Please fix or continue." and the AddOnly Order box is revealed (F.2.2); entering an Order (or just pressing Next again - blank order is accepted) adds the lot at print time and opens the Lot Panel; MB user without `BP_Add_Lot_PrintTime` gets "User not authorized to add lot records." (F.1.1 ok). Reset clears the values (a revealed Order box stays, empty).
- Label screen: single label type pre-selected, Test Print check box (default checked -> button reads "Test Print"), printer default "Microsoft Print To PDF", preview drop-down Select Option / View Master / View Preview / View Compare (FP.160323.F.5.1 ok), Reprint box forced on for an already printed lot.
- Date identifier (`..., Date, Protect`): input `txtFlexLot_Expires`, class `dpDate hasDatepicker`, readonly (Protect), jQuery datepicker format m/d/yy; minDate null for Claude01 (has BP_FlexPriorDate) (FP.160601.F.1.1 / 1.3 / 1.4 ok; F.1.2 US/EU formats and F.1.5 without the process not tested).
**Deviations from ValMaster:** FLX.190301.F.1.2 (DeleteLotIfExists N, existing lot/order for a different item): no error "Cannot update item number of an existing lot/order combination" - a SECOND lot row (same order + lot, other item) is created (lot key includes the item). FLX.190301.F.2.3 negative (Order + Lot entered, Item identifier not AddOnly): "No item found." instead of "Insufficient lot identifiers configured". Duplicate identifier -> Server Error (no friendly message). Requirement spells `BP_Add_Lot_Printtime`; the process is `BP_Add_Lot_PrintTime`.
**Specs:** Flex_Printing_Requirements (entry, lookup, add lot, messages, label screen options, Reset; creates MBFLX<stamp> lots, deleted in Lot Management), Flex_Printing_Config_Variants (Order+Item, Order+Lot, date identifier; config restored), Flex_Printing_Security (tile, add-lot authorization). Helpers `support/flex-print.ts`, `support/print-config.ts` (guarded edits; no Reset click - see gotchas).
**Gotchas:** CDP keystrokes do not reach this iframe (use FlaUI send-keys); `input[id$="txtItemNumber"]` can match two boxes under a bad config; Print Config Management's Reset button crashed the renderer ("Page crashed") on 2026-10-12 once saved criteria existed - remove criteria rows by hand instead; the page restores the previous criteria rows.
**Not covered:** real Test Print / print and the PrintStatus 'TestPrinted' (FP.160323.F.3.2, needs DB / Print History Inquiry which is down), LotDeBypass (grid), date formats (EU), BP_FlexPriorDate absent, Override_Lot_At_Print denial, AddLotReasonRequired.
