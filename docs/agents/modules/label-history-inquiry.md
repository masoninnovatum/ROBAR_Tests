## Label History Inquiry - Playwright-confirmed 2026-11-03 (`tests/Label-History-Inquiry/` Requirements + Security + Localization; requirements in `valmaster-label-history-inquiry.md`: 25 rows LHI.190725.*, all Active)
**What it is:** the page `InnoPages/LabelHistory/LabelHistoryInquiry?sp=GetLabelHistoryInquiryData&PageMode=Detail` (project `Innovatum.Pages.LabelHistory.MVC`, `LabelHistoryController`, view `LabelHistoryInquiry.cshtml`), menu record "Label History Inquiry" in "Reports and Inquiries" (process `Label_History`, help id none, URLData carries the stored procedure and the page mode). It finds `PrintHistory` records with `PrintStatus = 'Printed'` for a barcode scan or an Item Number + Lot Number, through the stored procedure `GetLabelHistoryInquiryData` (`@Barcode`, `@LotNumber`, `@ItemNumber`, `@PrintId`, `@GetColumnsOnly`, `@CountOnly`) and the function `fExtractGTINLotFromBarcode` (GS1 AIs 01 GTIN 14, 10 lot (terminated by `^`), 11 / 17 dates 6, 21 serial, 30 quantity; a barcode starting with `+` is not parsed). The match is `(RobarMasterData.Primary_DI_Number = <gtin> OR PrintHistory.ItemNumber = <item>) AND Lot = <lot> AND PrintStatus = 'Printed'` (join on item number + version), so a barcode scan only finds prints of items that have a Master Data record with that DI.
- **Page:** `#barcode`, `#itemnumber`, `#lotnumber`, `#btnRetrieveLabelHistory` ("Submit", beside the Lot field of the Item group, below the scan field), grid `tr.jqgrow` with columns Action, LabelType, UserID, OrderNumber, Lot, ExpDate, LCN, Printer, Reprint, **ReasonCode, Comments** (reprint signature data), PrintDate; a row's Actions menu offers "View Detail". The document-level Enter key runs the search (`keypress` 13 -> click on Submit). After a scan the page writes the lot parsed from the barcode into `#lotnumber` (the item field stays empty unless the server returns it).
- **View Detail** (needs `LH_ViewDetail`): a dialog "View Detail" (button Close) with an iframe `GetLabelHistoryInquiryDetails?storedProcedure=...&printId=...`: table "Column Name / Value" (LabelType, UserId, OrderNum, Lot, ExpDate, LCN, Printer, Reprint, ReasonCode, Comments, PrintDate), table "ShareName / ShareValue" (every print data value: I_Num, I_Desc, L_Num, L_Exd, ... S_LabelControl) and the printed label image (`GetLabelImage?printId=...`, JPEG). **When exactly one record is returned the dialog opens by itself** (F.5.3); with several (e.g. a print and its reprint of the same lot) the user clicks View Detail per row. PageMode can also be `Reconcile` / `Both` (LH_Reconcile / LH_ReconcileSign, a reconciliation signature dialog): not in the requirements, not tested.
- **Security:** `[Authorize(Roles = "Label_History")]` on the page (without it: 302, no tile), `[Authorize(Roles = "LH_ViewDetail")]` on the detail endpoint (302) and the View Detail menu item is disabled client-side. **`GetLabelImage?printId=<id>` has no authorization: it returns the label JPEG to a request with no session** (tracker). Print ids are `PID_<32 hex>`.
- **Localization (F.1.3):** a Spanish session translates the heading, the three field labels, the Item legend, Submit, the View Detail dialog title and the detail table captions ("ES - ..."); NOT translated: the dialog's Close button and the grid column headers (they are column names returned by the stored procedure).
- **Test data policy:** read-only on real prints: single `MBBQA8457561` + lot `CLPTP560850L` (print id PID_13F1726F..., `test-data/phi-fixture.json`), several `MI080301` + lot `CLPBR374765` (a print and its reprint). Print history cannot be deleted, so no prints are made.
- **Barcode scan, live (`Label_History_Inquiry_Barcode.spec.ts`):** needs a printed item that ALSO has a Master Data record whose Primary DI is the scanned GTIN. Created ONCE on 2026-11-03 with the user's OK: an APPROVED RobarMasterData record for the CL serial item `CLSerItm8455875` (version 0, Primary DI `00841646990001`, brand "CL Brand", approved by a Mass Approve job; MDM records cannot be deleted; the spec looks it up first and creates it only when missing - the second run reused it). Its real print: lot `CLSPL395711`, order `CLSPL395711O`, item version 0, Printed (PID_9F2A5C6B..., `phi-fixture.json` `usrSerial`). Chosen because its serial template binds no `md_*` share names, so the new record cannot block or change its printing (the MBBQA* items of the Multi Document Printing specs were left alone). Results: scan `01<DI>10<lot>` returns exactly the item + lot rows and fills BOTH `#itemnumber` (derived through the DI) and `#lotnumber` (F.2.4 met when a Master Data record matches); `01<DI>11<6>17<6>10<lot>^21<serial>` parses the same (AI 11 / 17 / 10 with `^` / 21 skipped correctly); a wrong GTIN or an unknown lot returns "No records to view"; Enter in the scan field submits; a single match opens View Detail by itself. **A barcode the parser cannot read (e.g. starting with `+`) returns 2 unrelated Printed records of MBUser1 with a BLANK lot** (the empty GTIN / lot are compared with blank columns): tracker.
- **Not covered:** AI 30 (quantity) and a serial-number match, Reconcile mode.
