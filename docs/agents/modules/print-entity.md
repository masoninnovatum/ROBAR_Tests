## Print Entity with PrintEntityRequired = Y - Playwright-confirmed 2026-10-08 (TST703, headless, `tests/Print-Entity/Print_Entity_Print_Screens.spec.ts` + `tests/Lot-Management/Lot_Management_Print_Entity.spec.ts`, 3/3 each)

- **Setup:** user set `PrintEntityRequired` = Y (+ restart). The MB test user (MBPWLogin01) needs **`Print_Label`** plus the screen's `BP_*_Option` (`BP_PrintByOrder_Option`, `BP_PrintByLot_Option`, `BP_PrintByOrderMulti_Option`, `BP_PrintByLotMulti_Option`, `BP_PrintByOrderLot_Option`, `BP_MultiDocumentPrint`). Without `Print_Label` every screen shows "User not authorized to print. Print_Label" and hides the Print Entity behavior (dropdown disabled).
- **Print screens (all six: Print by order / lot / order multi / lot multi / order lot / Multi Document Printing):** user with NO active entity -> "No active Print Entities associated with this user. Cannot proceed." and no dropdown (on load); ONE entity -> dropdown pre-selected and **disabled** ("Print Entity: England"); TWO -> editable dropdown, options ascending, default England (alphabetical; no print history for the MB user). Legacy screens: `select[id$="ddlPrintEntity"]`; Multi Document Printing's entity dropdown has no id (first `select` of the entry panel). Matches the formal PE_* scripts.
- **Lot Management (DynamicUI) with Y:** the grid lists only lots whose Print Entity the user holds; no entity -> "No records to view". The Add dialog's Print Entity `<select>` lists the user's entities (the seed user with `*` sees England, MLAUser1, ROBAR, Vendors; the seed user is only offered ROBAR when the setting is N). **Deviations from the formal script PE_LotManagment:** with NO entity the Add icon is still ENABLED (the script expects all icons disabled) and its dialog's Print Entity list is empty; with ONE entity the Add dialog's field is a one-option dropdown, pre-set but NOT disabled (the script expects it disabled).
- **Not covered yet:** an INACTIVE assigned entity not appearing, "last used entity" default after a print, Excel Import Print Entity rules with Y, the Print History entity filter, printing itself.


## Print Entity (Y) - printing, Excel Import, inactive entities - Playwright-confirmed 2026-10-08 (3/3 each; `Browser-Printing/Print_By_Order.spec.ts`, `Multi_Document_Printing_Print_Entity.spec.ts` HEADED with real Print to PDF; `Lot-Management/Lot_Management_Excel_Print_Entity.spec.ts`; `Print-Entity/Print_Entity_Inactive.spec.ts`)

- **Print by Order / Multi Document Printing with a real print (PrintEntityRequired = Y, AddLotReasonRequired = Y, seed user Claude01 = `*`):** the Print Entity dropdown lists England, MLAUser1, ROBAR, Vendors (ascending). The CHOSEN entity is written to the new lot (Lot Management shows it) and **the dropdown defaults to the LAST USED entity on the next visit** (proved by alternating: default ROBAR -> print with England -> next default England; default England -> print with ROBAR -> ROBAR). Print by Order: Shop Order -> Next -> Reason Code dialog -> the page resets (re-enter Item / Lot / Order and the entity) -> Lot Panel -> Next -> label screen -> Print to PDF. Multi Document Printing: the entity is the first `<select>` of the entry panel; Next with a new lot raises the same Reason Code dialog; print status via `GetPrinterStatus` `"PrintStatus":"success"`.
- **Lot Management Excel Import with Y** (MB user with `EI_Lots`, entity England): a blank PrintEntity cell, an entity the user does not hold (ROBAR) and a non-existent entity are ALL refused with the same generic message "Row 2 has an invalid value specifed for the PrintEntity column" (typo in the product; the formal script PE_LotManagment_Import expects "This column does not allow null values." and "Print Entity is not linked to the UserID"); the user's own entity validates and the job completes (`Status Completed`), the lot carries England.
- **Inactive entities:** Print Entity Management lists ROBAR / England / MLAUser1 / Vendors as Active and **`Mars` and `1240` (Germany) as inactive**. A user with ONLY Mars gets the hard block "No active Print Entities associated with this user. Cannot proceed." on Print by lot, Print by order and Multi Document Printing; a user with England + Mars gets England only (pre-selected and disabled). **Lot Management behaves differently:** for the MB user with Mars assigned (alone or with England) the Add icon is DISABLED, while England alone leaves it enabled.
- **Helper note:** `loginAs` now waits up to 45 s (then reloads once) for the login form: a fresh context intermittently failed to show it after heavy runs.
