## Codes Management - Playwright-confirmed 2026-10-08 (TST703, headless, 3 specs in `tests/Codes-Management/`)

- **What it is:** InnoPages `Codes/Management` (menu tile "Codes Management", group Settings, process **`View_Codes`**). A CriteriaFilter (`dvFilters[n]`, columns CodeType / Code / Description / Active, operators Contains, Does Not Match, Does Not Contain, In, Not In, Greater Than, Less Than, Exactly Matches, Is Blank, Is Not Blank) + **Retrieve Data** (`#btnRetrieveData`, an `<input>`, value not text) + jqGrid `#grdJqGrid` (Code Type, Code, Description, Active; pager 10/20/30; the grid loads ALL codes on open, ~190 rows). Footer icons Add (`#add_grdJqGrid`) / Edit (`#edit_grdJqGrid`); **no delete** (codes cannot be removed). Actions menu (`#drpMainActions`) = **Excel Import** only. The table is `Codes` (CodeEntry): CodeType + Code unique, Code max 30 chars, Description, Active Y/N.
- **Filter gotchas:** for CodeType / Code / Active the **Exactly Matches** Value is a `<select>` of existing values, every other operator is a text box (Is (Not) Blank hides it). `.fill()` on the wrong kind times out and the grid silently stays UNFILTERED - an exploratory run edited the first row (SendAllWFEmails/Workflow, description blank) because of that; restored (description set back to blank). **A Contains with an EMPTY value does not reload the grid** (previous result stays); use `Code Is Not Blank` for "all". Greater Than / Less Than compare as TEXT (Code > "0185" = 184 of 192). Filters are NOT remembered across page loads. `.jqgrow` `textContent` has no spaces between cells (match a cell with `td[aria-describedby$="_code"]:text-is(...)`).
- **Add / Edit dialog (`#editmodgrdJqGrid`, buttons `#sData` / `#cData`, errors in `#FormError`):** Code Type is a **select2 "tags" box** (type a new type + Enter creates it; typing an existing one selects the existing option), Code, Description, Active checkbox (default ticked, Y/N). Messages: "Code Type: Field is required", "Code: Field is required", "CodeType/Code combination already exists", "Code exceeds the maximum allowed 30 characters length", "Code Type exceeds the maximum allowed 30 chararacters length" (**typo "chararacters" is in the seed Localize_Codes.cs**). Blank description is allowed. **Edit: Code Type and Code are disabled**, only Description / Active change; double-click a row opens Edit; Edit with a row selected.
- **Excel Import (`Codes/FileSubmission` -> `JobSubmission`):** "Codes Excel Data Upload", Download Template = `Codes_Template.xlsx` (headers **CodeType, Code, Description, Active**, sheet Sheet1). Differs from Dictionary Management: choosing a file POSTs the form and reloads the frame (re-resolve the frame), the sheet list is `#sheetName2`, **Validate = `#btnSubmit`**, upload = **`#btnBeginUpload`** ("Begin Upload"), success text "Validation Successful" / "DisplayId: n Upload Successful" (no full stops), back link "Previous Page". Job Description is an id-less text box (the error grid pager has a `.ui-pg-input` too - exclude it; an empty description makes Begin Upload do nothing). Validation: blank Code / CodeType -> red cell "This column does not allow null values."; Code over 30 -> "The maximum length for this column has been exceeded...Maximum allowed: 30 characters."; duplicate rows -> "Duplicate row in Excel"; existing row -> "Row already in Database" + prompt "The following records will replace data in the database, do you want to proceed?" (No / X abort, Yes proceeds); Active accepts Y/N/YES/NO/1/0 (mapped to Y/N).
- **Defect candidate:** Active = "Maybe" PASSES validation ("Validation Successful") although `CodesDataValidator` calls `CheckForValue(Active, {Y,N,YES,NO,0,1})`; the upload then fails with an EMPTY red error dialog (no message) and nothing is created (`ConvertRowToEntity` does `Convert.ToChar("Maybe")`).
- **Security:** tile needs `View_Codes`; without `Web_Codes` the page opens read-only (Add / Edit icons disabled with the tooltip "User not authorized for this task Web_Codes", a warning banner, Actions menu will not open) and the **Update action is refused server side (HTTP 302)** - unlike Lot Management / DynamicUI. With `Web_Codes` everything works. Excel Import signer rights (controller `Authenticate`): **`EI_Codes` / `EI_Codes_Upd` are checked only when the file contains rows that already exist** and the message names ONE process (a signer with neither is told "EI_Codes_Upd"; with EI_Codes only "EI_Codes_Upd"; with EI_Codes_Upd only "EI_Codes"); for a NEW-rows-only file the signer is not checked at Authenticate but the server (`ImportData` -> `EI_Codes`) refuses it later and the page shows an EMPTY error dialog; nothing is created.
- **Test data:** codes can't be deleted; specs only create/edit codes of type `MBCodesTest` (`MBCT<stamp>`, `MBCT<stamp>B` per run, `MBCX<stamp>a/b` per Excel run, `MBSECX` once, `MBCT-A` from exploration). The Update-action security check POSTs `MBCodesTest/MBSECX` (created the first time).
