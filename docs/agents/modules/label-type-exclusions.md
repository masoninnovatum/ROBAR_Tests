## Label Type Exclusions - Playwright-confirmed 2026-11-03 (`tests/Label-Type-Exclusions/Label_Type_Exclusions_Requirements.spec.ts` + `Label_Type_Exclusions_Security.spec.ts`, helpers `lte-helpers.ts`)
**What it is:** a legacy ASP.NET page (`Innovatum/ROBAR/management/LabelTypeExclusion/ExclusionEdit.aspx`, source `Web/ROBAR/Management/LabelTypeExclusion` + `LTExclusionEditGrid`, table `LabelTypeExclusions` = Workstation + LabelType + LastTouch, access `LabelTypeExclusionDb`) that says which LABEL TYPES a WORKSTATION may not print. Tile process `Maintain_LabelType_Exclusions` ("Allows a user to edit label type exclusions"). The print side reads it: `LabelTypeExclusion.GetExcludedLabelTypes / WorkstationCanPrintLabelType` in `LabeltypeSelection` (Print by ... label type lists), `RobarPrintUser`, Multi Document Printing (`MultiDocPrintingService`), `PrintDB`. **Requirements: ValMaster has NO rows for this page** (searched Module "Label Type Exclusions", "Label Type Exclusion", "Label Type Management" ...; the only related formal script is `MDP_IncludesExcludes` of Multi Document Printing), so the notes come from source + live behavior and the tracker lists the missing traceability.
- **Anatomy:** title "Label Type Exclusion Maintenance"; left the multi-select `select[id$=lbWorkstations]` (AutoPostBack; workstations that PRINTED in the last 90 days or already hold an exclusion, sorted; TST703: LAN-PC, MASON-LAPTOP, TAMMY-SAMSUNG, VMSRVTST703 = REAL machines: never touch them) with the text box `input[id$=txtboxAddWorkstation]` + "Add" (`btnAddWorkstation`): the name only goes into the page's view state (a blank or duplicate name is ignored, the box is emptied); nothing is stored and a reload no longer lists it. Selecting one or more workstations builds `table.EditGridTable` (title "Exclusions"): optional `tr.SelectAllRow` (ONLY with 2+ workstations selected), `tr.LabelTypesRow` (an empty first cell, then one column per label type: 63 on TST703, sorted case-insensitively) and one `tr.WorkstationRow` per selected workstation (name cell, then one checkbox cell per label type). Footer text "Warning: All changes are immediately reflected in the database."
- **Behavior:** a tick posts back at once (the checkbox click handler is a CSP-safe `addEventListener` -> `__doPostBack`) and inserts the exclusion row; an untick deletes it (both write X_ audit rows with the signed-in user). After a reload the workstation is listed (it holds an exclusion) with the same boxes ticked. The Select All header boxes always START unticked (they do not reflect the rows): an unticked header click = "tick all" (no change when everything is ticked), a second click clears the label type for every selected workstation. A workstation with no exclusions and no prints disappears from the list again, which makes cleanup trivial (untick everything).
- **Security:** tile gated by the process; the page itself is refused by URL for a user without it (IIS "The resource cannot be found", HTTP 404, while the seed user gets it by the same URL) - positive finding.
- **Test-data policy:** only workstations named `CLWS<stamp>[B]`; every tick is cleared in `finally` and the spec asserts the CL workstations are gone and the real list is unchanged.
- **Not covered:** the print-time EFFECT (an excluded label type no longer offered / refused in Print by Lot, Multi Document Printing ...): it would need the exclusion on the machine the browser runs on (a REAL workstation name, e.g. MASON-LAPTOP), which would hide label types from real users; ask first. Also not covered: the workstation name's case / whitespace handling and very long names.
