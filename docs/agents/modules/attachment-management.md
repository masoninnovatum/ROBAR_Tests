## LM_Edit / AM_Edit formal scripts: how editing is meant to work (read 2026-10-15; \diskstation\backedup\#Unlocked_Test_Cases\Attachments\6.0.2_And_Up\LM_Edit.doc, AM_Edit.doc)
- **Prerequisite settings (LM_Edit):** Global Setting `AttachEditIncrementSeqNum` = N, owner `Innovatum.Pages.LinkAttachmentManagement.WCF` (N: an edit overwrites version 0, Sequence stays 0; Y: every edit adds a version, Sequence 1, 2, ..., and View / Download then show the version popup; changing it needs a ROBAR_ServiceHost restart); `MultiFileAutoPostMin` = **1**, owner `Innovatum.Sentinel.Plugin` (default 90; the Sentinel plugin's auto-post timer in minutes, hence "wait one minute" after closing the editor); `BrowserViewFileTypeExtensions` = .PDF,.TXT,.JPG,.JPEG,.BMP,.PNG; File Purpose codes incl. Redline etc.; Sentinel client installed on the workstation.
- **Editor prerequisite:** if Adobe Acrobat Reader DC is the editor, "Enable Enhanced Security" and "Enable Protected Mode at Startup" must be OFF (Preferences > Security (Enhanced)).
- **Steps:** an authorized user (FP_<purpose>_Edit) picks a .pdf row > Actions > Edit > it opens in the default editor; edit, File > Save, close the editor, wait one minute, View: the edits show (in Attachment Management the Sequence is 0 with N, 1 with Y). A .docx or .txt row (ATT3) must answer "This type of file cannot be edited" (script step 1.9, so the refusal is the EXPECTED result). Each Edit click writes an ACTIVITY record (Action = Edit; the script checks `Select * from Activity where UserID = ... and Action = 'Edit'`). A user without FP_<purpose>_Edit sees Edit disabled; FP_<purpose>_Edit_Override_Lock covers taking over a file locked by another user.
- **TST703 / this PC on 2026-10-15:** AttachEditIncrementSeqNum = N (ok), BrowserViewFileTypeExtensions ok, **MultiFileAutoPostMin = 90** (script wants 1), Acrobat on this PC has Protected Mode ON (HKCU\Software\Adobe\Adobe Acrobat\DC\Privileged bProtectedMode = 1) and every save (Ctrl+S, the Save icon, "Yes" when closing) opened "Save as" instead of saving in place, so no edit reached the server (Sequence 0, 596 bytes). Not changed: Acrobat preferences and Global Settings are the user's.

### Link Management Edit on a PDF: WORKS end to end (2026-10-15, Link_Management_Edit_Document.spec.ts, headed, 1 pass ~3.5 min)
Flow: upload a hand-built PDF, link it By Item (fixture item in test-data/link-actions-item.json), Link Management > row Actions > Edit > Sentinel prompt confirmed > the DocumentEdit plugin downloads the PDF to C:\Innovatum\SentinelClient\DocumentFolder\<staging id>\ and opens it in Acrobat Reader > pen (Draw Freehand, 4th icon of the left tool strip) stroke > **Save with the toolbar Save icon (or Menu > Save), never Save As** > **Menu > Exit application** > within ~10 s the plugin log shows "IncrementalSaveSentinelStaging - suceeded" and "Process_EditorExited ... Close succeeded" > View in Link Management shows the pen stroke (/Ink annotation, file 596 -> ~5.4 KB, single version because AttachEditIncrementSeqNum = N). Helper scripts/acrobat-pen-edit.ps1 clicks by position in ONE Acrobat window (largest visible window of the process id; refuses windows smaller than 800x500).
Gotchas: (1) Acrobat Reader Protected Mode must be OFF or Save opens "Save as" and nothing is saved; (2) closing the window / killing Acrobat before saving loses the edit, and killing Acrobat leaves the plugin in a bad state for the next Edit (kill the DocumentEdit plugin process to reset); (3) with the plugin alive from a previous Edit the file is re-opened without an exit handler; (4) answer "Yes" to "save changes before closing?" also opens Save as, so Save first; (5) TST703 still has MultiFileAutoPostMin = 90 and the edit arrived anyway after ~10 s (the folder watcher posts on save); (6) a .docx / .txt is refused by design (LM_Edit step: "This type of file cannot be edited"), see Link_Management_Actions.spec.ts.
