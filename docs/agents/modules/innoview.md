# InnoView (ValMaster re-check 2026-10-11, TST703; specs tests/Cross-Module/InnoView_Requirements + InnoView_Security, 1 pass each; requirements in valmaster-innoview.md)
- Legacy ASP.NET app inside the web menu tile "InnoView" (`Innovatum/innoview/Screens/MainMenu.aspx`, report pages `ViewReport.aspx?ReportName=...`); report definitions are seeded by `Innovatum.Install/ROBARDB/BaseProductTables/IVReports/IVReportsDefaultRecords.cs` (name, query, menu category, caption, summary, process). Category tree is collapsed; a category link expands it in place (postback). Each report page: prompts (text inputs, selects, date inputs) + Submit + Export; the result grid comes back on the same page; footer "ReportView <user> 7.0.3.20260". The in-frame "Main Menu" link returns to the tree (more reliable than closing and reopening the tab).
- Reports live on TST703 (category -> report): 21 CFR Part 11 Reporting -> Activity History, All Electronic Signatures, Alternate Item History, Failed Login History, Item Change Detail, Login History, Lot Data Override History, Lot Serial Numbers History, Lots Table History; Change Control -> Change Control Status, Production Release Exceptions; Database -> Table Definitions, Table Names; Destination Labeling -> Destination Labeling Session History; Items -> Approved Items, Search Items By Item Number, Unapproved Items; Label Control -> Label Control (a report named like its category); Print History -> View Print History, ... With Failed, ... Reprints; Sentinel -> AttachmentFiles, Sentinel ExeVersions, ... XTable, Sentinel Staging, Staging History; Templates -> Label Changes; Translations -> Translation Verification; User Print Entity -> X User Print Entity; Workflow -> Workflow By Status. **Config Settings** (seed: Get Codes / Global Settings / Processes / Security / Settings / Print Configurations) shows NO reports on TST703.
- Prompts: Label Changes (Label Type select, Label Name); Activity History / All Electronic Signatures (User, Workstation, Action selects, Start / End Date); Login History / Failed Login History (User, Workstation, Start / End Date); Item Change Detail (UserID select, Item, Version, Start / End Date); View Print History (UserID, Template, Item, Order, Lot, Print Entity, Workstation, Print Date Start / Finish); Approved Items (Description, ItemNumber, LabelName, Approver select); Unapproved Items (Description, ItemNumber, LabelName) returned no table (no unapproved items); Workflow By Status (Header Status, Description, Last User select, Last Status Start / End, Initiate Start / End); Label Control (LCN, Item Number, Label Type, Item Version, Master Data Version, Template Name / Version, Release By, Allow Print, Workflow ID, Label Master Key, ReleasedOn Lower / Upper Bound). Every report has an Export button.
- Security: tile needs `Login_InnoView`; the three Print History reports (the whole category) need `Innov_ViewPrintHist`; all other seeded reports carry no process (any InnoView user sees them).
- Deviations from ValMaster (also in dit-tracker.md): report names differ from IVFRS-3.10 - 3.14 / 3.7 / 3.8 / 3.9 ("User Activity History" is "Activity History", "User Electronic Signatures" -> "All Electronic Signatures", "User Login History" -> "Login History", "User Failed Login History" -> "Failed Login History", "User Item Detail Change" -> "Item Change Detail", "Print History with Failed Prints" -> "View Print History With Failed"); Activity History and All Electronic Signatures lack the SequenceNumber column (Login / Failed Login History have it); View Print History With Failed has "Printstatus" instead of PRINTFAILED; Label Changes also has Change Server and Id columns (superset, fine). Everything else (prompts, columns, Export) matched.
