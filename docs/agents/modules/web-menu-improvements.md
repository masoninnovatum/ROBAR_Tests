## New web menu ("Web Menu Improvements") - Playwright-confirmed 2026-11-02 (`tests/Web-Menu-Improvements/`, 6 specs; helpers `tests/support/new-web-menu.ts`, `tests/Web-Menu-Improvements/wm-helpers.ts`)
**What it is:** an alternate login screen + landing page for the SAME ROBAR system (users, security, data are shared): `http://<server>/ROBAR/` (IIS site `InnovatumWebMenu`, project `Innovatum.WebMenu`, MVC; main menu route `/ROBAR/WebMenu/MainMenu`). The legacy menu is `/innovatum/WebMenu/`. Source: `Innovatum.WebMenu` (`AccountController` login / expired password / timeout / log off / SSO, `WebMenuController` main menu / favorites / dashboards / notifications, `WebMenuDB`, `Views/WebMenu/MainMenuLayout.cshtml` = all the page script, `Views/Account/*`), localization defaults in `Localize_WebMenu.cs`, Global Settings (owner `Innovatum.WebMenu`): `PageTitle` ("ROBAR Web Menu"), `WebTimeoutInMinutes` (seed 60, TST703 = 5), `NotificationAttachmentFilePurpose` (NotificationAttachment), `HelpURL`, `DefaultHelpID` (10015), `SupportAPILocation` (blank = no "Submit Support Files" link), `AutoDocumentDefaultAuthUser`, `OpenID_*` (blank on TST703 = no external login button; the SSO requirements WMI.230612.F.1.1 / 1.2 / 1.4 / 1.6 / 1.7 / U.1 need an IdP and are NOT tested).
- **Login (`#userIDInput`, `#passwordInput`, `#langSelect`, submit "Log In", error `.text-danger`):** unknown user and wrong password = "Invalid UserID/Password" (F.1.3; a blank submit gives the same text); the language list is English first and selected, others come from the localization table (TST703 test rows are prefixed "ES - "); changing the language reloads `Account/Login` and loses `?moduleName=` (tracker row). Login URL after log off / timeout: `/ROBAR/` (+ `?errorKey=errTimedOut`). Direct GET of the main menu without a session = raw IIS 401 page (not a redirect). Browser title = Global Setting `PageTitle` ("ROBAR Web Menu"); the footer shows `<SERVER> - <version>`.
- **Landing page:** header `☰ Modules` (`#moduleDialogToggle`), dashboard link(s), `[UserID]` label (F.1.5), language select, Log off (`#logoffBtnA`), Help (`#helpBtnA`, opens `<server>/Innovatum/WebHelp/en/index.html?10015` in a new window; module-specific HelpID when a module is selected), bell (`#notificationsIcon`), gear (`#settingsIcon`, only when the user holds a Settings module). Modules sidebar `#mySidebar`: rows `#moduleListTBody tr` (`.moduleName` text, `title` = the security process, `.starImg`), alphabetical (culture compare, space before letters), hidden again by a second click or by picking a module; modules the user may not open are not listed (CLPROp01 sees only Password Reset + Prompt Samples; Prompt Samples has NO process). A module opens as a header tab (`#moduleList li`, close `.moduleCloseBtn` x) with an iframe in `#allIFrames`; closing the active tab returns to the dashboard (`showDashboard`).
- **Favorites:** star stores the module name in the user's environment (`SaveFavorites`); on the next load favorites sort first (alphabetical) and are preloaded silently in hidden iframes (`#allIFrames iframe[id^=moduleFrame_]`, spinner turns into a check mark) (F.7.5). Client side a new favorite is inserted at the TOP at once and un-starring only changes the image until a reload.
- **Settings (gear):** list `#menuSupportModuleListTBody`, modules named by app settings `SettingsModule1..n` = Dashboards Link Management, Dashboards Management, Notifications Link Management, Notifications Management (processes `Dashboards_Link_Management`, `Dashboards_Management`, `Notifications_Link_Management`, `Notifications_Management`); each is a Dynamic UI page (`InnoPages/DynamicUI/DynamicUI?Heading=<process>&Definition=DashboardsLink|Dashboards|NotificationsLink|Notifications`), alphabetical, hidden after a pick or a second click on the wheel, no wheel without any of the four. The pages are served by direct URL without the process (tracker). **Dynamic UI grids need one Retrieve before `#add_grdJqGrid` exists** (helper `openSettings`); Delete is `#del_grdJqGrid` then `#dData`.
- **Dashboards:** table `WebMenuDashboards` (ID, Name = key (duplicate = "Record already exists"), SourceURL, PlaceholderURLForIE, IECompatible Y/N, Active) and `WebMenuDashboardLinkages` (UserID / GroupID / PrintEntity each with `*`, DashboardName = ACTIVE dashboards only, Active). `GetDashboards` precedence: user+group+entity, user+group, user, group+entity, group, entity, `*`; a dashboard is listed once; one dashboard = `#dashboardA` link, several = `#dashSelectID` (the first is loaded; the pick moves to the top, is saved as the user's `SelectedDashboardID` and comes first at the next login; `#dashboardSelectCoverDiv` over the select switches back from a module tab). The shared default is "Demo Power BI" linked `*`/`*`/`*` (every user sees it; so "a user with NO dashboard" (F.5.13) cannot be tested without changing shared data). IE fields are Chrome-irrelevant.
- **Notifications:** `WebMenuNotifications` (Name, Message, AttachmentFileName = files with purpose NotificationAttachment, EffectiveBegin / End (date only, default today), DaysToKeepAfterExpiration numeric: "Field DaysToKeepAfterExpiration has rule NumericOnly") + `WebMenuNotificationLinkages` (UserID / GroupID / PrintEntity / NotificationName = notifications effective NOW only). Row action "Acknowledgement History" (grid UserID / AttachmentDownloadedOn / AcknowledgedOn, written by `AttachmentDownloaded` / `AcknowledgeNotification`). At login `HasNotifications` (unacknowledged) opens the modal popup `#notificationsDiv` (`#notificationsTBody tr`, Close `#closeNotificationsBtn`, checkbox `#notiCheckbox_<id>`, attachment link = `DownloadNotificationAttachment`); the bell loads all active ones incl. acknowledged (timestamp `yyyy-MM-dd hh:mm AM/PM`). Defects found: acknowledge closure bug, EffectiveEnd exclusive + DaysToKeep ignored, duplicates, raw HTML (tracker rows).
- **Timeout:** page cookie `InnoSession_PageTimeout` = now + `WebTimeoutInMinutes` (set by the page script at load; read earlier it can hold a far-future server value), refreshed only on `mousemove` over `#webMenuBody`; checked every 3 s: <= 60 s shows `#timeoutWarningDiv` ("Timeout Approaching", countdown `#timeoutTimeLeft`, backdrop), <= 0 posts `Account/TimedOut` -> login page "Timed out due to inactivity" (Timeout Activity record written). Another user's login in the same browser changes cookie `InnoSession_CurrentUser`, which times the older tab out. The server session is NOT ended on timeout (tracker). A hand-edited `InnoSession_CurrentUser` cookie gives an IIS Runtime Error (the cookie is decrypted server side) - use a real second login. The spec moves the timeout cookie instead of waiting or touching the setting.
- **Expired Password page:** see modules/login-and-passwords.md (messages, order); spec `WebMenu_Expired_Password` re-verifies F.2.3-F.2.10 live (Submit is never disabled, F.2.6).
- **Test data policy:** the specs create only deletable rows (notifications, dashboards, links: all deleted in `finally`); fixture user CLPROp01 / group CLPRGrp (Password-Management fixtures, seed password) is the notified / security-gated user; the seed user is never linked to a notification (its popup would block every later new-menu login) and its favorites are cleared again. `WebMenu_Expired_Password` rotates CLPRTgtA01's password (`test-data/pr-fixture-passwords.json`).
- **Not covered:** SSO / OAuth2 / OKTA (F.1.1, 1.2, 1.4, 1.6, 1.7, U.1: no IdP configured), F.5.13 (no dashboard), IE placeholder URL behavior, attachment-less `Submit Support Files` module (needs `SupportAPILocation`), Power BI content, `PasswordChangeDays` expiry (F.2.1) and AD / SSO exclusion (F.2.2), the DB rows (USERS / X_USERS / Activity: no database access).
